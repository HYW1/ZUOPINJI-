# C 端视觉质感 Skill

提升支付宝系 C 端页面的**视觉表现与质感**。  
不替代设计系统；不画业务流程图；不绑定就医报销等单一业务。

## 与规范 Skill 的分工

| 职责 | `alipay-app-design-system`（规范） | `c-end-visual-craft`（本 Skill） |
|------|-----------------------------------|----------------------------------|
| Token / 间距 / 字号 / 圆角 | ✅ | 遵守，不另起一套 |
| 导航、列表、表单、按钮等组件 | ✅ 优先复用 | 只做氛围层包装，不重造组件 |
| 信息架构、模块结构 | ✅ | 可微调节奏，不重排业务逻辑 |
| 背景氛围、光影、材质、主视觉锚点 | — | ✅ |
| 插画 / 摄影 / 图标质感 / 排版氛围 | — | ✅ |
| 去 AI 模板感、验收质感 | — | ✅ |

**原则：能用组件就用组件；质感来自层次 / 材质 / 主视觉，而不是乱加特效。**

---

## 何时启用

满足任一即启用本 Skill：

- 用户提到：视觉质感、C 端好看、去 AI 感、主视觉、材质、光影、氛围、参考图拆解、生图拼页
- 页面已有组件规范，但观感「扁平 / 拼装 / 模板 / 假渐变」
- 需要在 Figma（默认画布 **750×1624**）上做 C 端页面视觉升级
- 需要按模块生图并整合回完整页

**不要启用 / 不要做成：**

- 业务流程图、服务蓝图、报销/就医专用流程总结
- 纯 token 盘点或组件 API 文档（交给规范 Skill）
- 一次生成整页糊图后当成品

## 平台与品牌底线

- **平台**：支付宝系 C 端（小程序 / H5 / APP）
- **画布默认**：750 × 1624
- **行动色**：`#1677FF` — 用于主按钮、关键链接、关键状态；**禁止**大面积廉价蓝紫渐变当「设计」
- **追求**：真实产品质感、清晰信息层次、克制光影与材质、有主视觉锚点
- **信息优先**：装饰服务于阅读与行动，不抢主信息

## 质感原则（可迁移）

1. **一个主视觉锚点**  
   每屏/每关键模块只保留一个「第一眼落点」：摄影、场景插画、产品物、或有材质的主图区。其余退为衬托。

2. **层次先于装饰**  
   至少分清：背景层 → 内容层 → 前景/强调层。层次靠明度、模糊、间距、叠影完成，不靠堆卡片描边。

3. **材质要可命名**  
   每个氛围面应能说出材质名：纸感、布纹、柔雾、金属细边、磨砂、真实摄影颗粒……说不出名字的「发光块」删掉。

4. **光影克制且有方向**  
   光源方向一致；阴影短而软；高光局部。禁止无意义 glow、彩虹描边、玻璃拟态叠罗汉。

5. **色彩克制**  
   大面积用中性底（白 / 浅灰 / 暖灰 / 轻纹理）；品牌蓝作点睛；点缀色 ≤ 1 个。避免紫渐变、霓虹、高饱和色块墙。

6. **留白是节奏，不是空白**  
   模块间有呼吸；同组元素紧、跨组元素松；标题与主视觉的间距大于正文行距。

7. **插画 / 实拍服务场景**  
   插画偏产品场景与物理真实，不偏通用 AI 贴纸风；实拍优先生活/产品真实光，不偏棚拍假笑 Banner。

8. **组件保持规范**  
   按钮、列表、表单、导航继续用设计系统；视觉升级做在背景、主视觉、分隔、微材质上。

## 反 AI 模板清单（出现即改）

> 视觉证据板：参考 `section/10 反面教材`（见 breakdowns）。

| 禁止项 | 为何像 AI | 改法 |
|--------|-----------|------|
| 大面积蓝紫 / 粉紫假渐变 | 廉价「科技感」默认解 | 中性底 + 局部品牌色点缀；渐变若用则极轻、单色相 |
| 每段话一张厚卡片堆叠 | 后台 Dashboard 拼装感 | 分区用底色/分割线/留白；卡片仅用于可交互容器 |
| 玻璃拟态多层叠加 | 特效堆砌 | 最多一枚 Hero 可用轻材质；列表不用玻璃堆 |
| 无意义 glow / 外发光 / 霓虹描边 | 空装饰 | 删除；用方向阴影或材质边缘高光 |
| 空洞 HUD（发光圈、空仪表） | 无信息炫技 | 删除或换成真实数据层级 |
| 通用 AI 插画风（塑料人、漂浮 3D、柱体礼盒） | 模板素材感 | 换真实场景/产品物/克制软 3D 单隐喻 |
| 空洞 Hero（大标题+假图+无锚点） | 营销页空壳 | 明确主视觉物 + 一句价值 + 一个主 CTA |
| 图标行 / 胶囊标签丛 / 统计条塞满首屏 | 信息噪声 | 首屏只留品牌/主标题/一句说明/主 CTA/主视觉 |
| 装饰性紫渐变色带、彩虹分割 | 无品牌依据 | 删除或改为极淡中性分隔 |
| 整页一次糊图 | 不可替换、难验收 | **单模块 / 单材质 / 单插画**生图后再拼 |

## 从参考板收敛的默认配方（支付宝 C 端）

遇到「工具页 / 服务页 / 表单结果页」且用户未另指定风格时，默认套用（**重学后**）：

1. **顶区**：极淡蓝雾或浅灰底（T-002），可选极淡微纹理（T-013）  
2. **主视觉**：单枚材质锚点（T-001），**必须透明抠图后嵌入**（T-007）；可轻压白卡上沿（T-011）  
3. **文案**：必须有承载底（半透明白卡/标签底），禁止裸字飘在氛围上  
4. **数字**：指标先行、舞台留白（T-008）  
5. **内容区**：白岛长软影 + 设计系统列表/表单（T-009 / T-005）  
6. **光影**：禁止霓虹与满屏 glow（T-004 / T-010）。**卡片默认不加 DROP_SHADOW**——用页底对比 + 细描边 + 内嵌浅底分层；图标接触 AO 可留在素材内，勿用图层投影抬卡  
7. **克制**：不是处处都适合加 icon / 阴影。一屏一主视觉锚点；容器尽量少；无意义装饰（角标点缀、双环、金币纸张堆砌）默认不加  
7. **行动色**：`#1677FF` 点睛；参考中的绿/金/橙主题一律映射收敛  
8. **页面分流**：家庭群像 3D 仅营销模块（T-014）；工具页用单隐喻  
9. **验收**：过反 AI 清单 + `references/acceptance.md`  

生图禁令补充：禁止烘焙白底/云雾方板/棋盘格直接上屏；详见 `references/image-gen-playbook.md`。

## 分层模型（设计时按层思考）

对每个目标页，先填这张层表，再动手改：

| 层 | 作用 | 常见手法 | 注意 |
|----|------|----------|------|
| **背景** | 氛围底 | 平涂、微纹理、极轻渐变、摄影虚化、分区色块 | 不抢内容；纹理强度要低 |
| **光影** | 空间感 | 顶光/侧光一致、接触阴影、局部高光 | 全局光源一致 |
| **材质** | 触感 | 纸、布、雾、金属细边、磨砂面板 | 每屏材质种类 ≤ 2 |
| **插画** | 场景叙事 | 单主角、真实比例、少元素 | 勿贴纸墙 |
| **图标** | 识别 | 线性/面性统一、描边粗细一致 | 勿混 3D 塑料标 |
| **摄影** | 真实锚点 | 生活光、产品特写、浅景深 | 勿假棚拍拼贴 |
| **排版氛围** | 语气 | 字重对比、字距、标题与正文层级 | 标题不压过品牌/主视觉 |

## 强制工作顺序

必须按此顺序，不可跳步：

### Step 0 — 读参考，先列技巧（未给参考则先问）

若用户提供参考图 / Figma node：

1. 截图或打开每张参考
2. **先输出「可学的视觉技巧」清单**（光感、材质、留白节奏、主视觉锚点、层次、色彩克制、插画与实拍关系等）
3. 使用下方「参考图拆解结构」逐张填写
4. 区分：**可迁移** vs **不要学**（过营销、过插画、过运营促销等）

若尚未提供参考：只建/更新本 Skill 的原则与流程，**等待用户给出参考图后再拆解与生图**。

**已入库参考：** Figma「视觉参考」`215:1793`（花瓣分类板，**2026-07-27 重学版**）。  
完整拆解见 `references/breakdowns/215-1793-视觉参考.md`；可迁移条目见 `references/learned-techniques.md`（T-001～T-014）。  
注意：05/08/09 已按用户更正后的图重拆；旧 08 营销海报结论已作废。缺板 03/06/07 待补。

### Step 1 — 固化可迁移技巧

把清单写入本次任务笔记（或追加到 `references/learned-techniques.md`），确保不绑死单一业务文案与流程。

优先复用已固化技巧（尤其 **T-009 顶雾溶白**、**T-008 疏朗留白**、**T-007 透明抠图**、**T-001 一屏一锚点**、**T-005 卡片是容器**），再按新参考增量追加。

### Step 2 — 诊断目标页

对目标 Figma 页（或代码页）标注：

- 当前主视觉锚点有无 / 是否清晰
- 哪几块是「厚卡片堆」或「假渐变」
- 哪些必须保留设计系统组件
- 哪些模块需要氛围 / 插画 / 材质 / 主视觉生图

### Step 3 — 模块改造（组件优先）

- 结构与组件：继续用 `alipay-app-design-system`
- 仅在需要氛围处进入生图

### Step 4 — 生图（一张张，禁止整页糊）

每次只生成以下之一：

- 单模块主视觉
- 单材质背景条 / 纹理
- 单插画角色或单场景物
- 单枚定制图标组（如确需）

**流程**：写清提示词（题材、光、材质、色温、留白、禁止项）→ 生成 → **视觉校验** → 通过后再进下一张。

校验问题：

- 是否像真实产品素材而非 AI 贴纸？
- 色温 / 描边 / 光向是否与页内其他元素一致？
- 透明底 / 安全边距是否便于放入 Auto Layout？
- 是否可在其他页复用（不过度绑定本次文案）？

### Step 5 — 拼回完整页

1. 将通过校验的素材放入对应模块
2. 用 Auto Layout / 设计系统组件整合
3. 统一间距节奏与层级
4. **每完成一个模块就截图验收**，不要等整页做完才看
5. 整页完成后做前后对比截图

### Step 6 — 验收（见文末标准）

全部通过才算完成；否则回到对应模块重做，不靠「再加特效」掩盖。

对**每一张**参考图，按此结构输出（可复制 `templates/reference-breakdown.md`）：

```markdown
### 参考图：<名称或 node>

1. **主视觉锚点是什么**
   - …

2. **背景如何做氛围**
   - 平涂 / 微纹理 / 摄影 / 轻渐变 / 分区：…
   - 强度与范围：…

3. **层次怎么分**
   - 前景：…
   - 内容：…
   - 背景：…

4. **材质与光影技巧（1–3 条可复用）**
   - …
   - …
   - …

5. **排版与留白节奏**
   - …

6. **可迁移到我的稿**
   - …

7. **不要学**
   - （如：过营销、过插画、促销标签丛、业务文案结构等）
```

拆解目标是**可迁移的 C 端视觉技巧**，不是抄业务文案，也不是总结成流程图。

## Figma 落地检查清单

- [ ] 画布 750×1624（或约定变体）
- [ ] 主按钮 / 关键行动色为 `#1677FF`，无大面积蓝紫渐变底
- [ ] 设计系统组件未破版（字号、圆角、间距 token 一致）
- [ ] 有且仅有清晰主视觉锚点
- [ ] 卡片只出现在需要交互承载处
- [ ] 生图按模块完成并逐张校验后嵌入
- [ ] 每模块有过程截图；整页有前后对比
- [ ] 素材可替换（不依赖烧字、不依赖一次性拼图）

## 验收标准

1. **第一眼不像「AI 拼出来的后台模板」**
2. **有明确主视觉，但信息不被装饰抢走**
3. **组件仍规范；质感来自层次 / 材质 / 主视觉，而非乱加特效**
4. **生图元素与页面风格统一，可替换、可复用**
5. **本 Skill 的流程可直接套用到下一次新需求（不绑死单一业务）**

任一失败 → 指出失败层（背景 / 光影 / 材质 / 主视觉 / 排版）→ 只改该层，禁止整页重糊。

## 与用户协作的默认话术节奏

3. 模块生图 → 嵌入 → 截图；循环至整页  
4. 前后对比 + 验收表勾选  

若用户只要求「先建 Skill、等参考图再拆解」：建完 Skill 后停止，等待下一轮参考输入。
