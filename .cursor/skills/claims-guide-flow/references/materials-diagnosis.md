# 材料核对诊断页

## 定位

已就医路径的结果页 = **材料核对诊断**，不是支付成功式空庆祝页。

用户需要立刻知道：

1. 能不能申请  
2. 齐了几项 / 缺几项  
3. 缺的是什么、怎么补  
4. 下一步点哪里  

## 信息架构（固定顺序）

```text
结论 > 统计 > 清单 > 规则/帮助 > 行动
```

| 层 | 作用 | 示例 |
|---|---|---|
| 结论 | 一句话状态 | 已核对，可申请理赔 / 已预存材料，待收齐 |
| 统计 | 可扫读的数量 | 已保存 3 · 识别成功 3 · 待处理 0 |
| 清单 | 可操作的材料行 | 门诊病历 / 医疗票据 / 费用明细清单 |
| 规则/帮助 | 卡住时的出口 | 材料准备有困难？咨询理赔向导 |
| 行动 | 唯一主按钮 | 材料齐全，申请理赔 |

## 多份材料排序规则

对清单内材料（及同类型多张图）排序：

1. **异常置顶** — 待处理、识别失败、缺页、需重拍优先于正常项  
2. **核心凭证优先** — 默认业务顺序：  
   - 门诊/出院病历（或出院小结）  
   - 医疗发票 / 医疗票据  
   - 费用明细清单  
   - 其他补充材料  
3. **同类型按就诊时间降序** — 最近的在前  
4. **必传先于选传** — 同优先级下必传在上  

不要按「上传时间」或「文件名」打乱业务优先级。

## 材料行最低字段

- 材料名称  
- 必传 / 选传（或「必需」）标签  
- 状态（已齐、未上传、识别失败…）— 可用缩略图区表达  
- 示例入口（问号 / 「示例」）  
- 一句诊断或要求（缺什么时必填）  

## 状态文案对照

| 状态 | 结论语气 | 主按钮 |
|---|---|---|
| 齐全可申请 | 已核对，可申请理赔 | 材料齐全，申请理赔 |
| 预存未齐 | 已预存材料，待收齐 | 去补齐材料 / 继续准备材料（与产品一致） |
| 有失败项 | 有材料需处理 | 去处理 / 重新上传 |

统计标签与结论必须同故事：不能结论说「可申请」而待处理 > 0 且无解释。

## 视觉注意

- 成功结论可用绿色点缀（图标/短条），不要整页大绿底板。  
- 列表用白卡 + 内部分割，避免每张材料一张厚阴影卡。  
- 缩略图区保持可点选/替换的操作暗示（如「移动」、删除），但不抢主按钮。
