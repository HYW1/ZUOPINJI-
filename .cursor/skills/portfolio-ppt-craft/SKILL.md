# 设计师作品集 PPT 视觉质感 Skill

提升设计师**作品集 PPT / 面试 Demo Deck**的视觉表现、叙事节奏与版式质感。  
去 AI 模板感；信息与作品截图优先。

不替代：不写简历文案策略；不代写项目业务结论；不画服务蓝图 / 流程图当作品。

---

## 与相邻 Skill 的分工

本仓库目前**没有**独立的「内容 / 叙事 / 简历文案」类 Skill。  
因此本 Skill 明确边界如下：

| 职责 | 内容 / 叙事（用户或其它 Skill） | `portfolio-ppt-craft`（本 Skill） |
|------|--------------------------------|----------------------------------|
| 项目故事、信息架构、简历文案策略 | ✅ | ❌ 不重写项目故事，只做表达层 |
| 业务结论、指标口径、面试口述稿 | ✅ | ❌ 不代写结论；可建议「字少到哪」 |
| 服务蓝图 / 流程图当作品本体 | ✅ 若用户自备真实过程稿 | ❌ 不新画流程冒充作品 |
| 画布系统、页边距、栏宽、标题区、页码 | — | ✅ |
| 封面 / 章节页氛围、案例主视觉锚点 | — | ✅ |
| 字体层级、留白节奏、材质背景 | — | ✅ |
| 去 AI 模板感、落地检查、验收 | — | ✅ |
| Figma / Keynote / Slides 版式落地 | — | ✅ |
| 单张材质 / 装饰 / 插画生图（非整页糊） | — | ✅ |

**原则：不重写项目故事，只做表达层。**  
质感来自**层次 / 材质 / 排版节奏 / 一页一锚点**，而不是乱加特效。

若日后出现「内容 / 叙事」类 Skill：那边管故事与信息架构；本 Skill 只管视觉质感与版式落地——分工表按上表执行。

## 何时启用

满足任一即启用本 Skill：

- 用户提到：作品集 PPT 质感、面试 Demo Deck、去 AI 感、封面 / 章节页氛围、案例页主视觉、字体层级、留白、材质背景、参考拆解
- 需要把作品集落到 **Figma / Keynote / Slides**，观感「模板 / 海报墙 / Dashboard 卡片堆」
- 需要按页诊断并做版式系统 + 单张生图拼回

**不要启用 / 不要做成：**

- 一次生成整本 PPT 糊图后当成品
- 用空洞炫技页替代真实作品截图 / 过程稿
- 把作品集做成营销海报墙或 Dashboard 卡片堆
- 代写简历策略、项目业务结论、服务蓝图当作品
- 没有真实作品图时靠插画 / AI 假 UI 充数

## 平台与画布底线

- **画布默认**：**1920 × 1080**（16:9）；可选稿幅 **1440 × 810**（同比例缩小，便于稿面标注）
- **气质**：专业、克制、可投屏、可打印 PDF；偏「设计作品展示」，而非「运营大促」
- **色彩**：大面积中性底（白 / 浅灰 / 暖灰 / 近黑其一为主）；点缀色 ≤ 1；**禁止**大面积蓝紫 / 粉紫假渐变当设计
- **字体**：标题与正文层级清晰（字重 / 字号阶梯）；禁止满屏同粗细；禁止装饰字体滥用
- **作品真实性**：界面截图 / 动效帧 / 过程稿必须真实可辨；**禁止**用假 UI 糊图冒充作品
- **信息优先**：装饰服务于叙事与阅读，不抢作品本身

## 作品集 PPT 特有规则（强制）

1. **一页一事**  
   每页只讲一个点；演讲者口述补充，不把段落堆进 PPT。

2. **图真字少**  
   界面 / 流程 / 探索稿必须可读；说明文字 ≤ 必要标注（标注式，非作文式）。

3. **系列感**  
   全册像同一人做的：统一页边距、标题区、正文字号阶梯、强调色用法；禁止每页换皮肤。

4. **封面测试**  
   去掉姓名后，仍应看得出「这是设计作品集」，而非「科技公司招商 PPT」。

5. **禁止用装饰掩盖弱项目**  
   没有作品图就减页，不靠插画 / 假 UI / 炫技页充数。

6. **动效**  
   若做，只服务翻页节奏与焦点；禁止无意义漂浮、循环炫光、粒子雨。

---

## 质感原则（可迁移 · PPT 语境）

1. **一页一主视觉锚点**  
   每页只保留一个「第一眼落点」：封面人 / 项目主图 / 关键界面 / 过程物——**二选一为主**，其余退为衬托。禁止双主锚抢戏。

2. **层次先于装饰**  
   至少分清：背景层 → 内容层 → 强调层。层次靠明度、间距、叠影、栏系统完成，不靠厚卡片描边墙。

3. **材质要可命名**  
   每个氛围面应能说出材质名：纸感、柔雾、细金属边、光滑 mesh、轻磨砂面板……说不出名字的 glow / 霓虹删掉。

4. **光影克制且有方向**  
   全册光源方向尽量一致；阴影短而软；高光局部。禁止无意义 glow、彩虹描边、玻璃拟态叠罗汉。

5. **色彩克制**  
   大面积中性底；点缀色 ≤ 1；作品截图可带品牌色，但版式点缀不另开第二套彩虹。

6. **留白是节奏**  
   演讲页（封面 / 章节 / 开场）更疏；信息页可密但必须成组。标题区与主图间距大于正文行距。

7. **截图 / 摄影服务叙事，不做贴纸墙**  
   真界面压过装饰；多图时有主次与对齐，不做「每格一张假手机框」。

8. **版式系统保持一致**  
   全册统一：页边距、栏宽、标题区位置、页码、章节标识。换页只换内容，不换坐标系。

## 反 AI 模板清单（PPT 专用 · 出现即改）

> 详细勾选版见 `references/anti-ai-checklist.md`。

| 禁止项 | 为何像 AI | 改法 |
|--------|-----------|------|
| 大面积蓝紫 / 粉紫假渐变封面 | 廉价「科技感」默认解 | 中性底 + 真实作品锚点；渐变若用则极轻、单色相 |
| 每段话一张厚阴影卡片堆叠 | Dashboard / 后台拼装感 | 分区用留白 / 分割线 / 底色差；卡片仅承载可交互或必须成组的信息 |
| 玻璃拟态 / 无意义 glow / 霓虹描边 | 特效堆砌 | 删除；用方向阴影或可命名材质边缘 |
| 空洞 3D 塑料人、漂浮礼盒、通用 AI 插画墙 | 模板素材感 | 换成真实作品截图 / 过程稿 / 克制单隐喻 |
| 图标行 + 胶囊标签丛 + 假数据统计条塞满首屏 | 信息噪声 | 封面 / 首屏只留姓名角色一句 + 一个真实锚点 |
| 同心圆 / 雷达弧 / 地形细线当背景装饰 | 空洞科技皮 | 改为可命名柔雾或干净平涂 |
| 颗粒感 / film grain / 砂面噪点当「质感」 | 假胶片滤镜 | 删除；材质用纸感 / 柔雾 / 细边，而非噪点糊 |
| 整页一次生图糊完当成品 | 不可替换、难验收 | **单材质 / 单装饰 / 单插画**生图后再拼 |
| 假手机框 + 模糊看不清的界面冒充作品 | 造假作品 | 换真实可读截图；看不清就裁近或减页 |
| 「Before / After」做成营销对比海报 | 运营大促感 | 做成可阅读设计说明：问题 → 改动点 → 结果，图真字少 |
| 满页英文废话大词（Synergy / Elevate / Next-gen） | 空洞营销腔 | 删除；改成具体角色 / 约束 / 设计动作 |

## 默认配方（作品集 PPT · 用户未另指定风格时）

遇到互联网产品设计作品集且用户未另指定风格时，默认套用：

### 封面
- [ ] 极克制中性底（平涂或极淡柔雾，禁紫渐变 / 禁颗粒）
- [ ] 姓名 + 角色一句（如「产品设计师」）
- [ ] **一个**真实作品锚点（主界面 / 主项目静帧），或空白舞台留给人像 / 主项目
- [ ] 通过封面测试：去姓名仍像设计作品集

### 目录 / 章节页
- [ ] 大数字或短章节名 + 大量留白
- [ ] 不做插画堆、不做图标宫格目录墙

### 案例开场
- [ ] 问题一句 + 角色 / 约束一句
- [ ] 主界面真图作锚点（可读）
- [ ] 禁止开场页堆满标签 / 假仪表盘

### 过程页
- [ ] 最多 **3** 个信息块（三联上限）
- [ ] 图大于字；字是标注不是作文
- [ ] 探索稿 / 线框 / 关键帧必须可辨

### 结果页
- [ ] 指标少而真（有来源或可口述）；禁止假仪表盘 / 假百分比墙
- [ ] 结果界面或关键对比真图优先

### 全册统一
- [ ] 页边距一致（建议 ≥ 64px @1920，或约定后锁死）
- [ ] 标题栏位置 / 正文字号阶梯 / 强调色用法一致
- [ ] 页码与章节标识位置固定
- [ ] 过反 AI 清单 + `references/acceptance.md`

生图禁令补充：禁止整页糊图、禁止假 UI、禁止烧字进主视觉；详见 `references/image-gen-playbook.md`。

## 分层模型（设计时按层思考）

对每个目标页，先填这张层表，再动手改：

| 层 | 作用 | 常见手法 | 注意 |
|----|------|----------|------|
| **背景** | 氛围底 / 投屏可读底 | 平涂、极淡柔雾、轻分区色块 | 不抢作品；禁紫渐变墙、禁雷达线、禁颗粒当质感 |
| **光影** | 空间感 | 顶光 / 侧光一致、短软接触影、局部高光 | 全册光向一致；禁满屏 glow |
| **材质** | 触感 | 纸感、柔雾、细金属边、光滑 mesh、轻磨砂 | 每页材质种类 ≤ 2；必须可命名 |
| **插画** | 辅助隐喻（非作品本体） | 单主角、克制、少元素 | 勿贴纸墙；无作品图时禁止用插画充数 |
| **图标** | 识别 / 目录辅助 | 线性或面性统一、描边粗细一致 | 勿混 3D 塑料标；封面慎用图标行 |
| **摄影或截图** | **真实作品锚点** | 可读界面、动效帧、过程稿、人像（若有） | 假手机框 + 模糊 UI 一票否决 |
| **排版氛围** | 叙事语气 | 字重对比、字号阶梯、疏密节奏、标注式正文 | 一页一事；演讲页疏、信息页成组密 |

## 强制工作顺序

必须按此顺序，不可跳步：

### Step 0 — 读参考，先列技巧（未给参考则先问）

若用户提供参考图 / Figma node / Keynote·Slides 导出页：

1. 截图或打开每张参考
2. **先输出「可学的视觉技巧」清单**（锚点、留白节奏、材质、层次、色彩克制、截图与字的关系等）
3. 使用下方「参考图拆解结构」逐张填写
4. 区分：**可迁移** vs **不要学**（过营销、过海报、假 UI、运营大促等）

若尚未提供参考：只建 / 更新本 Skill 的原则与流程，**等待用户给出参考图后再拆解与生图**。

**已入库参考：** Figma「作品集PPT参考」`252:1793`（多板整合，**2026-07-27**）。  
完整拆解见 `references/breakdowns/252-1793-作品集PPT参考.md`；可迁移条目见 `references/learned-techniques.md`（T-001～T-020）。  
方法对照：同文件 C 端「视觉参考」`215:1793`（不把 C 端业务图当作品集内容）。  
重分类准则：封面≠功能页；章节≠框架图；结果≠假仪表盘；空洞 glow/招贴皮进反面区。  
`01 封面与舞台` 已按 `pin.it/2iCHloZtk`「封面/封底」分区整区入库（42 Pins）；另有 `09 背景垫图材质` / `10 作品集设计分析` / `11 方案分析`（来源见拆解文档短链表）。

### Step 1 — 固化可迁移技巧

把清单写入本次任务笔记，或追加到 `references/learned-techniques.md`（编号续写 T-xxx），确保不绑死单一项目内容与业务结论。

优先复用已固化技巧（尤其 **T-001 一页一锚点**、**T-013 疏朗封面**、**T-015 有限叠景深**、**T-016 标注式正文**、**T-019 母版坐标系**、**T-020 反面闸门**），再按新参考增量追加。

### Step 2 — 诊断目标页 / 整册

对目标 Deck（或单页）标注：

- 当前主视觉锚点有无 / 是否清晰 / 是否双锚抢戏
- 哪几页是「厚卡片堆」「假渐变」「贴纸墙」「假 UI」
- 哪些真实作品图 / 过程稿**必须保留**
- 哪些页需要氛围 / 材质 / 辅助插画生图（非整页）
- 版式系统是否统一（页边距、标题区、字号阶梯、页码）

### Step 3 — 版式改造（先系统后装饰）

- 先锁全册系统：画布、页边距、栏、标题区、页码、章节标识、字号阶梯、点缀色
- 再按页做一页一锚点与疏密节奏
- 仅在需要氛围处进入生图

### Step 4 — 生图（一张张，禁止整页糊）

每次只生成以下之一：

- 单材质背景 / 柔雾底
- 单装饰元素（可命名材质）
- 单枚辅助插画或单隐喻物
- **从不**生成「整页假 PPT / 假作品界面」当成品

**流程**：写清提示词 → 生成 → **视觉校验** → 通过后再进下一张。

校验问题：

- 是否像作品集投屏素材，而非营销海报 / AI 贴纸？
- 色温 / 光向是否与全册一致？
- 是否便于放入版式（安全边距、可替换、无烧字）？
- 是否可在其它页复用（不过度绑定本次项目文案）？

### Step 5 — 拼回页面并每页截图验收

1. 将通过校验的素材放入对应页
2. 用统一版式系统整合（Figma Auto Layout / Keynote 母版 / Slides 母版）
3. **每完成一页就导出 / 截图验收**，不要等整册做完才看
4. 整册完成后做前后对比（至少封面 + 1 案例开场 + 1 过程页 + 1 结果页）

### Step 6 — 终验收

全部通过 `references/acceptance.md` 才算完成；否则回到对应层重做，不靠「再加特效」掩盖。

## 参考图拆解结构（输出模板）

对**每一张**参考图，按此结构输出（可复制 `templates/reference-breakdown.md`）：

```markdown
### 参考图：<名称或 node / 页码>

1. **主视觉锚点是什么**
   - …

2. **背景如何做氛围**
   - 平涂 / 柔雾 / 轻渐变 / 分区：…

3. **层次怎么分**
   - 前景：…
   - 内容：…
   - 背景：…

4. **材质与光影技巧（1–3 条可复用）**
   - …
   - …
   - …

5. **排版与留白节奏**
   - …

6. **可迁移到我的稿**
   - …

7. **不要学**
   - （如：过营销、假 UI、海报墙、卡片堆、业务文案结构等）
```

拆解目标是**可迁移的作品集 PPT 视觉技巧**，不是抄别人项目内容，也不是代写业务结论。

## 落地检查清单（Figma / Keynote / Slides 通用）

- [ ] 画布 1920×1080（或约定 1440×810 同比例稿）
- [ ] 全册页边距 / 标题区 / 页码 / 章节标识位置一致
- [ ] 标题与正文字号阶梯清晰；无满屏同粗细
- [ ] 大面积中性底；点缀色 ≤ 1；无大面积蓝紫假渐变
- [ ] 每页有且仅有清晰主视觉锚点（一页一事）
- [ ] 作品截图 / 过程稿真实可读；无假 UI 糊图
- [ ] 过程页信息块 ≤ 3；结果指标少而真
- [ ] 生图按单张完成并逐张校验后嵌入（无整页糊）

## 验收标准

1. **第一眼不像「AI 模板 PPT / 招商科技皮」**
2. **有明确主视觉锚点，但不抢真实作品信息**
3. **全册版式系统一致；质感来自层次 / 材质 / 排版节奏，而非乱加特效**
4. **生图元素可替换、可复用；作品图真实可读**
5. **本 Skill 的流程可直接套用到下一本作品集（不绑死单一项目）**

任一失败 → 指出失败层（背景 / 光影 / 材质 / 截图 / 排版）→ 只改该层，禁止整册重糊。

## 与用户协作的默认话术节奏

1. 确认目标 Deck / 页范围 + 参考图是否齐全；确认真实作品素材是否齐  
2. 先输出参考拆解与「可学技巧」清单，再改稿（无参考则停，等参考）  
3. 先锁版式系统 → 按页改锚点与节奏 → 单张生图 → 嵌入 → 每页截图；循环至整册  
4. 前后对比 + 验收表勾选  

若用户只要求「先建 Skill、等参考图再拆解」：建完 Skill 后停止，等待下一轮参考输入。
